# RICE DOCTOR

เว็บต้นแบบภาษาไทยสำหรับให้ AI ประเมินคลาสจากภาพใบข้าว พร้อมคำอธิบายและแนวทางตรวจสอบเบื้องต้น รองรับหน้าจอมือถือและคอมพิวเตอร์

## เปิดใช้งาน

เปิด `index.html` ในเบราว์เซอร์ได้โดยตรง หรือวางโฟลเดอร์นี้บนเว็บเซิร์ฟเวอร์แบบ static

เมนูสามขีดมุมซ้ายบนเปิดแถบด้านข้างสำหรับตรวจข้าว ประวัติ คู่มือ และข้อมูลโครงการ บนคอมพิวเตอร์ย่อเป็นแถบไอคอนได้ บนมือถือเปิดเป็นเมนูเลื่อนพร้อมฉากหลัง ปุ่มเข้าสู่ระบบมุมซ้ายบนเปิด `account.html` ในแท็บใหม่ แยกหน้าสมัครสมาชิกและจัดการบัญชีออกจากหน้าตรวจข้าว

ควรเปิดผ่าน HTTP/HTTPS เมื่อใช้บัญชีร่วมกันหลายแท็บ เพื่อให้การเก็บ session และการแจ้งเปลี่ยนบัญชีของ Supabase ทำงานบน origin เดียวกัน ไฟล์ `account.html`, `account.css`, `account.js`, `navigation.css`, `navigation.js` และ `supabase-config.js` ต้องอยู่ข้าง `index.html` เมื่อย้ายหรือเผยแพร่เว็บ

## ฟังก์ชันที่ทำงานได้

- เลือกรูปใบข้าวจากอุปกรณ์และดูตัวอย่างก่อนตรวจ ภาพไม่ถูกอัปโหลดไปยังเซิร์ฟเวอร์
- อัปโหลดภาพแล้วให้ AI จำแนกคลาสจากภาพโดยตรง ไม่ต้องเลือกอาการหรือระยะการเจริญเติบโต
- แสดงสรุปคลาส คะแนนจากโมเดล คลาสทางเลือกอีก 2 อันดับ คำอธิบาย แนวทางตรวจ และจัดการเบื้องต้น โดยไม่ต้องเลือกอาการหรือระยะการเจริญเติบโต
- แนวทางตรวจโรคข้าวไทยอ้างอิง Rice Knowledge Bank ของกรมการข้าว และใช้เป็นข้อมูลประกอบการคัดกรอง ไม่ยืนยันผล AI
- วิเคราะห์รูปใบข้าวด้วย MobileNetV2 ONNX แบบ multi-label 17 output labels ซึ่งทำงานในเบราว์เซอร์ และมีคำแนะนำตรวจต่อประกอบผล
- คัดลอกสรุป หรือใช้หน้าพิมพ์ของเบราว์เซอร์เพื่อบันทึกเป็น PDF
- เก็บประวัติไม่เกิน 8 รายการใน `localStorage` ของเบราว์เซอร์เครื่องนั้น
- ล้างข้อมูลของการตรวจปัจจุบันได้
- เชื่อมประวัติ Supabase แบบสมัครผู้ใช้ชั่วคราวโดยไม่ต้องใช้อีเมล และแยกประวัติด้วย RLS

## สถานะล่าสุด — 19 ตุลาคม 2026

เว็บใช้ MobileNetV2 + MLP แบบ multi-label 17 outputs ครอบคลุม 13/14 โรคตามคู่มือ ขาดโรคหูด (Rice gall dwarf). ฝึกจาก Roboflow Raw Dataset v1, IoT-RiceMobileNet และ Philippines Rice Diseases (Kaggle). สิทธิ์ตามที่ผู้เผยแพร่ระบุคือ CC BY 4.0, CC BY 4.0 และ AGPL-3.0 ตามลำดับ; ยังไม่ได้ตรวจสิทธิ์ภาพต้นฉบับทุกภาพเป็นรายภาพ

หลังยุบ SHA256 ซ้ำมี 5,539 ภาพ แบ่ง train/validation/test 3,864/835/840 ภาพ โดยเก็บกลุ่มภาพคล้ายจาก pHash ไว้ใน split เดียวกัน ไม่มี SHA256 หรือกลุ่ม pHash ข้าม split. ยังไม่ใช่การแยกตามแปลง/ต้นข้าว และอาจเหลือภาพครอปที่ตรวจซ้ำไม่พบ

ผล holdout: macro-F1 17 outputs 88.15%; macro-F1 13 โรคเป้าหมาย 88.12%; micro-F1 81.84%; top-1 อยู่ในป้ายจริง 83.57%; ตรงทั้งชุดป้าย 69.76%. **ไม่ใช่ผลทดสอบอิสระจากแปลงไทย และไม่ยืนยัน 80% ทุกโรค**. โรคไหม้ F1 74.4%, กาบใบเน่า 74.1%; คลาสหายากบางคลาสมี test เพียง 8–15 ภาพ

โมเดลปัจจุบันอยู่ที่ `models/rice-grouped-17class/` อ่านรายละเอียด สิทธิ์ ผลรายคลาส และการตรวจ export ใน `MODEL_CARD.md`, `evaluation.json`, `verification.json`, `coverage.csv`. หน้าเว็บโหลด `model-data.js` และใช้ ONNX Runtime Web/WASM จาก CDN; ภาพประมวลผลในเบราว์เซอร์

## ขอบเขตโรคตามคู่มือที่แนบ

หน้าเว็บมีคู่มือสังเกตอาการและตรวจต่อครบ 14 โรคจากเอกสาร “โรค-แมลงศัตรูข้าวและการป้องกันกำจัด” โมเดลภาพครอบคลุม 13 โรค เหลือโรคหูดที่มีคู่มือแต่ยังไม่มีคลาส AI

โฟลเดอร์ IoT-RiceMobileNet ที่ผู้ใช้ให้มามีภาพที่จัดป้ายกำกับ 6 คลาสเท่านั้น จึงไม่สามารถฝึกโมเดลเพิ่มให้จำแนกโรคอีก 10 โรคจากโฟลเดอร์นี้เพียงอย่างเดียวได้ การเพิ่มคลาสต้องใช้ภาพที่ได้รับอนุญาตและตรวจป้ายกำกับรายโรคให้ถูกต้อง พบ [โมเดลสาธารณะ 17 คลาส](https://huggingface.co/Huyt/rice-leaf-disease-efficientnet-b0) ซึ่ง weights ระบุ Apache-2.0 และครอบคลุมโรคหลายรายการที่ขาด แต่ผู้จัดทำรายงานว่าคลาสหายากบางโรคมีภาพทดสอบราว 15 ภาพ/คลาส และยังไม่มีการประเมินกับภาพแปลงไทย จึงยังไม่ได้นำมาแทนโมเดลปัจจุบัน

## แหล่งข้อมูลโรคข้าวของไทย

คำอธิบายและขั้นตอนตรวจต่อในหน้าเว็บเรียบเรียงจาก [Rice Knowledge Bank ของกรมการข้าว](https://rkb.ricethailand.go.th/web/content_page.php?code=A-VIVSO5ZWMG) และหน้าความรู้โรคข้าวรายโรค เว็บแสดงลิงก์อ้างอิงไว้ในส่วน “แนวทางตรวจโรคที่อ้างอิงข้อมูลไทย”

กรมการข้าวยังเผยแพร่ [ข้อมูลการสำรวจการเกิดโรคและแมลงศัตรูในแปลงนาเกษตรกร](https://catalog.ricethailand.go.th/en/dataset/) ภายใต้ Open Data Common แต่ข้อมูลนี้เป็นตารางสำรวจ ไม่ใช่ชุดภาพใบข้าวสำหรับฝึก AI และหน้าเว็บต้นแบบยังไม่ได้ดึงข้อมูลสำรวจเข้ามาแสดงหรืออัปเดตอัตโนมัติ

เว็บจึงระบุโรคเป็น “อาการอาจสอดคล้องกับ” และเสนอรายการตรวจต่อเท่านั้น ไม่ควรใช้ยืนยันโรคหรือสั่งการใช้สารกำจัดโรคจากภาพเพียงอย่างเดียว

## ตั้งค่าบัญชีและประวัติ Supabase

1. เปิด Authentication > Sign-in / Providers แล้วเปิด **Anonymous Sign-Ins** และ **Email provider** ในโปรเจกต์ Supabase
2. เปิด SQL Editor แล้วรัน `supabase/schema.sql` เพื่อสร้างตารางประวัติและ RLS
3. เว็บเตรียม Project URL และ Publishable key ของโปรเจกต์นี้ไว้แล้ว หากเปลี่ยนโปรเจกต์ให้อัปเดตค่าที่ “ตั้งค่าประวัติออนไลน์” เท่านั้น ห้ามใช้ Secret/service_role key ในเว็บ
4. สำหรับสมัคร/ยืนยันอีเมลบนเว็บที่เผยแพร่ ให้กำหนด Site URL และ Redirect URLs เป็นโดเมน HTTPS ของเว็บใน Authentication > URL Configuration; หน้า `file://` ใช้ทดสอบหน้าจอได้ แต่ไม่เหมาะกับลิงก์ยืนยันอีเมล
5. หากต้องการให้ผู้ใช้เปลี่ยนบัญชีชั่วคราวเป็นบัญชีอีเมลโดยเก็บประวัติเดิมไว้ ให้เปิด **Manual Linking** ใน Supabase Auth ตาม [เอกสาร Supabase](https://supabase.com/docs/guides/auth/auth-anonymous#convert-an-anonymous-user-to-a-permanent-user)

ผู้ใช้ใช้ต่อแบบไม่สมัครได้ หรือสมัคร/เข้าสู่ระบบด้วยอีเมลและรหัสผ่านจากส่วน “บัญชีผู้ใช้” การผูกบัญชีจากผู้ใช้ชั่วคราวใช้การยืนยันอีเมลก่อน แล้วจึงตั้งรหัสผ่าน; ผู้ใช้ที่มีบัญชีแล้วสามารถล็อกอินจากเครื่องอื่นได้ การลืมรหัสผ่านส่งลิงก์รีเซ็ตไปยังอีเมล ระบบใช้ฐานข้อมูลเดียว แต่ RLS แยกแถวประวัติตาม `user_id` ของบัญชี แต่ละบัญชีอ่าน เพิ่ม และลบได้เฉพาะประวัติของตนเอง

บันทึกเฉพาะสรุปผลและคะแนน ไม่อัปโหลดภาพหรือชื่อไฟล์ ข้อมูลประวัติในเบราว์เซอร์แยกตามรหัสบัญชี ส่วนค่า URL และ Publishable key เก็บใน `localStorage` เพื่อเชื่อมต่อซ้ำได้ รหัสผ่านไม่ถูกบันทึกใน `localStorage`

## Community Water Bank MVP

หน้า `water-bank.html` ใช้บัญชี Supabase/Auth ชุดเดียวกับเว็บ RICE DOCTOR และเปิดจากเมนู “ธนาคารน้ำชุมชน” เกษตรกรส่งคำขอและติดตามคำขอของตน ส่วนบัญชีที่ได้รับมอบหมายเป็น `committee` หรือ `admin` จะเห็นลิงก์ Admin dashboard (`water-bank.html?admin=1`) สำหรับจัดการทะเบียนแหล่งน้ำ ตรวจคำขอ วางตารางจัดสรรด้วยตนเอง และบันทึกปริมาณส่งน้ำจริง โดยสิทธิ์ข้อมูลแต่ละชุมชนยังตรวจซ้ำที่ Supabase RLS/RPC

Admin dashboard มีทะเบียนแหล่งน้ำแยก `บ่อเติมน้ำใต้ดิน` ออกจาก `บ่อสูบใช้งาน`; บ่อเติมน้ำไม่ถูกนับเป็นน้ำสำหรับสูบจ่าย ไม่มีข้อมูลบ่อหรือน้ำตั้งต้น ระบบไม่จัดสรรน้ำอัตโนมัติ และคณะกรรมการต้องกำหนดแผนและบันทึกผลส่งจริงเอง

### เปิดใช้ฐานข้อมูล

1. เปิด Supabase SQL Editor ของโปรเจกต์เดียวกับบัญชี RICE DOCTOR แล้วรัน `supabase/water-bank.sql` หลังจาก `supabase/schema.sql`
2. ผู้ดูแลระบบสร้างแถวจริงใน `water_communities` และเพิ่มบัญชีคณะกรรมการใน `water_community_staff` โดยใช้ UUID ของบัญชีจาก Authentication > Users ตัวอย่างคำสั่งอยู่ท้ายไฟล์ migration; ให้แทนค่าด้วยข้อมูลที่ยืนยันกับชุมชนแล้ว
3. คณะกรรมการเข้าสู่ระบบด้วยบัญชีอีเมล RICE DOCTOR แล้วจึงเพิ่ม/แก้ทะเบียนแหล่งน้ำและพิจารณาคำขอได้ เกษตรกรที่เข้าสู่ระบบด้วยบัญชีจริงส่งคำขอได้ ส่วนบัญชีชั่วคราวถูกปฏิเสธ
4. ชุมชนเป็นผู้กรอกชื่อแหล่งน้ำ สถานะ และปริมาณพร้อมจัดสรรเอง ไม่มีข้อมูลบ่อจริงตั้งต้น บ่อเติมน้ำใต้ดินจะไม่ถูกเลือกเป็นแหล่งสูบจ่าย

RLS จำกัดคำขอให้เจ้าของคำขอและคณะกรรมการของชุมชนเห็นได้เท่านั้น การอนุมัติ การบันทึกแผน และการบันทึกส่งจริงทำผ่าน RPC ที่ตรวจบทบาท สถานะ ปริมาณอนุมัติ ปริมาณแหล่งน้ำ และยอดส่งสะสมในฐานข้อมูล การแก้บทบาททำโดยผู้ดูแล Supabase ใน SQL Editor เท่านั้น ไม่มีปุ่มสมัครเป็นคณะกรรมการในหน้าเว็บ

เว็บไซต์นี้ยังไม่มีทะเบียนแปลงหรือข้อมูลแปลงให้ผูกอยู่ในฐานข้อมูล จึงมีช่องชื่อแปลง/เลขแปลงเป็นข้อความอ้างอิงที่เกษตรกรกรอกเอง ไม่สร้างหรืออ้างข้อมูลแปลงแทนระบบเดิม การจัดสรรเป็นการตัดสินใจของคณะกรรมการ ไม่ใช่ AI และบันทึก “ส่งน้ำจริง” ต้องมาจากผู้ดูแลบันทึกหลังปฏิบัติงาน

### ขอบเขตไฟล์สำหรับเผยแพร่

ระบบ AI ที่หน้าเว็บเรียกใช้คือ `models/rice-grouped-17class/model-data.js`; รายงานโมเดลและใบอนุญาตที่เกี่ยวข้องอยู่ในโฟลเดอร์เดียวกัน ข้อมูลโมเดลทดลองอื่น ชุดฝึก และไฟล์นำเสนอไม่จำเป็นต่อการเปิดเว็บหลัก

## ขอบเขตที่ต้องมีจากเจ้าของโครงการ

- โมเดลจริงต้องฝึกด้วยชุดภาพที่มีสิทธิ์ใช้และติดป้ายกำกับโรค/อาการอย่างถูกต้อง โค้ดรองรับการเชื่อมโมเดลแล้ว แต่ไม่มีการฝึกหรือปลอมผลโมเดลแทนข้อมูลจริง
- Supabase ต้องเปิด Anonymous Sign-Ins และ Email provider, รัน SQL schema และกำหนด Site URL/Redirect URLs ก่อนเผยแพร่ระบบสมัครอีเมล
- ไฟล์ SQL พร้อมรันแล้ว ส่วนตารางและนโยบาย RLS จะเริ่มทำงานเมื่อเจ้าของโครงการนำ SQL ไปรันในโปรเจกต์ของตน

## สถานะค้นหาโมเดลครบ 14 โรค

ผลสำรวจแหล่งภาพ ใบอนุญาต และความครอบคลุมรายโรคอยู่ใน [AI-RESEARCH-STATUS.md](AI-RESEARCH-STATUS.md) โมเดลปัจจุบันยังไม่ครอบคลุม 14 โรค และยังไม่มีชุดทดสอบจากแปลงไทย. ค่า macro-F1 85.7% เป็นผล 8 labels จากชุดทดสอบภายในสองแหล่งภาพเท่านั้น ไม่ได้ยืนยันว่าโมเดลทำได้ 80% สำหรับ 14 โรค.
